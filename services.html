Services / priced on request

Eight pours. Each one is a service you can hire.

Each Bedrock service is a listing on the CommandAGI marketplace, run by Bedrock agents and overseen by Bedrock people. You open a thread, agree the scope, and sign the contract in CommandAGI. Escrow holds payment until you accept the work.

Pricing: on request. A quote states the scope, the grants it needs and the time it covers.

Compute and cloud

Nimbus and Terra

Nimbus / compute marketplace

Compute, placed for the job

What you get. Machines of the size and region your job needs, with access you control and a usage record for each one.

How it works. The Nimbus agent reads the job in your thread, proposes machines and their cost bounds, and waits for your approval. It starts and releases machines only inside the grant you set.

Priced on request.

Terra / cloud infrastructure

Networks, stores and queues, drawn first

What you get. A cloud environment with its networks, data stores, queues and access rules, written as a plan you can read before anything exists.

How it works. The Terra agent drafts the plan in the thread. You approve each change. Every change is logged with the principal that sent it, so you can see who did what and when.

Priced on request.

Connectors and developer ecosystem

Nexus and Hatch

Nexus / enterprise SaaS connectors

Your tools, wired to your threads

What you get. Connections to the ticketing, billing, storage and CRM tools your team already uses, each with the fields and actions you allow.

How it works. Nexus holds each credential in the host's secret store, never in a file or a log. Each connection is a grant with a scope, and you can revoke it in one step.

Priced on request.

Hatch / developer ecosystem

Pipelines, registries and review

What you get. CI/CD pipelines for your repository, package and image registries, and a review step on every change before it ships.

How it works. The Hatch agent writes the pipeline as a file in your repo. Its runs are recorded. A review agent checks each change, and a person you name signs off before a release. The developer guide, the bedrock-docs site, has the detail.

Priced on request.

Security, communications and browser identity

Sentinel, Vox and Proxy

Sentinel / cybersecurity substrate

Checks you can audit

Secrets handling, dependency and configuration review, access logs and incident runbooks. Each check is an agent run with its inputs and outputs kept on record.

Priced on request.

Vox / unified communications

One fabric for mail, text and calls

Email, text, calls and calendar events arrive in the right thread. Consent for each channel is recorded before the first message goes out.

Priced on request.

Proxy / browser identity infrastructure

Browsers that sign in as you allow

Managed browser profiles and sign-in state for automation, with a permission for each site. Proxy never signs in to a site outside its grant.

Priced on request.

Identity and trust

Verity

Verity / identity and trust layer

KYC and KYB checks other services can verify

What you get. Know-your-customer checks for people and know-your-business checks for companies, and an attestation that another service can verify without seeing the underlying file.

How it works. Verity runs each check through its own agents and a person who signs the result. It issues attestations beneath the identity root. The root stays with the people who hold it. Read how the trust chain works.

Priced on request.
